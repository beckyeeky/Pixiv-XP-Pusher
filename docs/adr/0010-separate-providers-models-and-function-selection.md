# Separate Providers, Models, and function selection

External-service configuration uses typed Providers that own credentials and type-specific fields, while LLM and Embedding Models select a known or custom model from one Provider. Product functions such as Classification Maintenance reference Models through selection lists; Pixiv and Danbooru reference their typed Provider directly. LLM and Embedding Providers may have multiple configured instances; Pixiv and Danbooru are singleton Providers. Credentials remain in the local `config.yaml` initially, but authenticated Web APIs expose only a masked fingerprint and support replacement or explicit deletion rather than readback. This replaces per-Judge credentials and avoids exposing implementation terms such as “connection” in the UI, while retaining a custom OpenAI-compatible LLM Provider path for private gateways and unsupported services.
