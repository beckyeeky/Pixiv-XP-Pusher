# Use bounded cached vectors only for Exploration retrieval

Semantic vector retrieval is an independently configurable candidate source for the Exploration lane. It reads only a model-compatible current Preference Profile vector and a bounded recent slice of existing work-vector cache, computes cosine similarity in-process, and hydrates a bounded number of candidates before the common Filter, Daily Slate, and Identity Cap path. It does not generate vectors during retrieval, activate Tag Aliases, or modify Normalized Tags. A vector index remains out of scope until measured cache volume makes this bounded scan inadequate.

Retrieval source and Recommendation Motive remain distinct audit concepts, but candidates introduced by this source are eligible only for the Exploration lane so vector similarity cannot silently expand Feature or identity quotas. Each run persists its source, similarity, Model, retrieval/final ranks, selection outcome, Preference Profile concentration, auxiliary Slate profile-support concentration, and duplicate-semantic rate. Feedback is joined read-only at evaluation time so the source can be evaluated and released independently from work-level `semantic_weight` calibration.
